Uncertainty: prediction sets

Instead of one overconfident answer, the app returns a set of plausible crops. It uses split conformal prediction, calibrated on {{ metrics.conformal.n_calibration }} rows the model never trained on.

  • Target coverage: {{ '%.0f'|format(metrics.conformal.target_coverage * 100) }}%
  • Measured on the test set: {{ '%.1f'|format(metrics.conformal.empirical_coverage * 100) }}%
  • Average set size: {{ '%.2f'|format(metrics.conformal.mean_set_size) }} crops ({{ '%.0f'|format(metrics.conformal.single_crop_fraction * 100) }}% are a single crop)
  • No crop above the bar: {{ '%.0f'|format((metrics.conformal.fallback_fraction or 0) * 100) }}% of test inputs; for these the three best guesses are shown

The guarantee is averaged over inputs and assumes new data resemble the calibration data. It can fail under distribution shift.

Unusual-input check

Each input is compared with the pooled training data using the Mahalanobis distance. Combinations beyond the {{ '%.0f'|format(metrics.ood.quantile * 100) }}th percentile of training distances ({{ '%.2f'|format(metrics.ood.threshold) }}) get a warning.

{{ '%.1f'|format(metrics.ood.test_flag_rate * 100) }}% of test rows are flagged. The training data forms one cluster per crop, so this only catches inputs far from the whole cloud.

What drives predictions

Limitations

  • The dataset is small and balanced (the same number of examples per crop) and looks cleaner than real farm data, so scores here will not transfer directly to real fields.
  • The model sees only seven inputs. It does not know the soil type, location, season, irrigation, market prices or pests.
  • Inputs outside the training ranges trigger a warning, because predictions there are unreliable.
